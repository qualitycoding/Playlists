# Decisions
Amended 2026-11-07 (R4) after the independent pre-mortem and adversarial review; "[R4]" marks an amendment. Finding-to-decision mapping: plan/AMENDMENTS.md.

D-001 Actions sole live sync executor; Pages read-only.
D-002 no Express API on Pages.
D-003 public status allowlist only.
D-004 encrypt state or keep outside public repo; no plaintext fallback. [R4] Scheme, key lifecycle and rollback detection: D-035.
D-005 legacy cache unknown until remote read-back. [R4] Legacy matches are re-validated first: D-032, D-037.
D-006 per-destination completion.
D-007 reconcile membership before insert. [R4] Only for rows in the unknown state; identity and completeness rules: D-034.
D-008 exact unique artist/title; reject edition/year/track conflicts. [R4] Normalisation, search depth, year rule and recall floor: D-032.
D-009 master/genre add-only.
D-010 Recently Added alone replaced after validation and snapshot. [R4] Exact semantics: D-033.
D-011 no YT Recently Added.
D-012 Discogs errors/incomplete pages abort before writes. [R4] Completeness checks: D-034.
D-013 fix unsupported SpotifyOAuth refresh_token kwarg via verified Spotipy token handling; invalid_grant requires reauth. [R4] The rotated refresh token is persisted inside the encrypted state, never in a plaintext cache file: D-035.
D-014 mutation testing opt-out first cycle.
D-015 missing playlist ID hard failure. [R4] Plus distinctness, ownership and capacity preflight: D-023.
D-016 remove browser secrets/token exchange/Firebase/Drive routes unless justified. [R4] Local server routes: D-039.
D-017 verify Spotipy method against current Spotify API max100.
D-018 ytmusicapi gated; evaluate official YouTube Data API. [R4] Gate evidence: D-038.
D-019 no history rewrite without G-005.
D-020 least privilege, contents:write only state commit. [R4] Enforced by the job split in D-030.
D-021 BLOCKED pending research/reviews/audits.
D-022 CI matrix is limited to ubuntu-24.04 x86_64; no ARM64/musl/Windows/macOS coverage is promised without further intake and evidence.

D-023 [R4] Target preflight before any write: all nine target IDs pairwise distinct; each playlist owned by the authenticated user; Recently Added differs from every add-only ID; remote Recently Added holds at most 100 items, otherwise abort; target not full against the provider capacity limit (limits unverified, A-025). Targets must be private unless the owner accepts public exposure in writing at G-002a (the playlist-modify-public scope is dropped if unused).
D-024 [R4] Circuit breaker for unsupervised runs after G-002b: abort if additions exceed new matched releases x K tracks, or if any add-only target's remote count has fallen since the last verified run; a manual-dispatch override input requires a logged reason. K is set from measured fixture data before G-002b (starting value 40 is unmeasured, A-026). The first run after migration is capped at a stated number of releases with resumable progress; the collection count (count only) is recorded in S-000.
D-025 [R4] Concurrency: workflow concurrency group "sync" with cancel-in-progress false. The state push fetches and rebases then retries; a push still rejected after provider writes fails the run red and the next run reconciles those rows from the unknown state. Each batch is deduplicated by provider URI before writing, so two releases sharing a master add each track once.
D-026 [R4] Exit-code contract: 0 all configured targets verified; 2 partial (some targets verified); 1 fatal. A configured target with missing or invalid credentials is fatal, never skipped. A dry-run exits 0 and its status is labelled dry-run, never success.
D-027 [R4] Collection privacy in outputs: logs, step summaries, artefacts and committed gate evidence carry only counts, run URLs and keyed hashes of identifiers (HMAC key held in the encrypted state); no artist, title, release row, account identifier or provider response body. Raw evidence stays in encrypted state or a short-retention artefact. Verified with a canary collection row (T-052, T-045).
D-028 [R4] Gate integrity: live-write and deploy secrets live in a GitHub Environment restricted to main with the owner as required reviewer; every live workflow job is guarded by github.ref == refs/heads/main; CI accepts a GATE-<id>.md only if it was added by a commit authored or approved by the owner, never by a bot or the implementing agent. Availability on this repository is unverified (A-022) and is checked in S-000; if unavailable the owner chooses an alternative before G-002a.
D-029 [R4] G-002 has two stages. G-002a: rehearsal on disposable private playlists and a preview Pages build, using mocked and recorded evidence. G-002b: first write to the real playlists, production Pages deploy and re-enabling of the schedule, after T-040 passes and the recall report exists.
D-030 [R4] Workflow hardening: secrets reach a step only through env on the consuming step, never through ${{ secrets.* }} inside run or if; the YouTube auth file is written with printf '%s' from env or decoded from base64; the sync job holds provider secrets and read-only contents and uploads encrypted state; a separate commit job holds contents:write and no provider secrets; pip install uses --require-hashes, npm uses npm ci, actions are pinned to SHAs, runner is ubuntu-24.04; one Python minor version is chosen and recorded in S-000 (candidates 3.12 and 3.13, not yet verified on the runner); the legacy scheduled workflow is disabled in S-000 and re-enabled only at G-002b.
D-031 [R4] Status delivery and staleness: the sync workflow deploys the status itself (a push made with GITHUB_TOKEN does not trigger other workflows); the dashboard shows STALE when the last success is older than 8 days and labels dry-run status distinctly; the owner checks monthly that the schedule is still enabled (GitHub disables scheduled workflows in public repositories after 60 days without activity; whether bot commits count is unverified, A-024).
D-032 [R4] Matching specification: normalise with NFKC and casefold; strip Discogs disambiguation suffixes "(n)" and trailing "*" name variations; treat "Various" as a compilation by an explicit rule; escape quotes in provider queries; request K results (K>1, stated in S-004, unmeasured) and judge uniqueness over all K; compare against the master release year where Discogs provides one, not the pressing year; reject edition and track conflicts as in D-008. Before G-002b a private labelled fixture from the owner's collection reports precision and recall with a recall floor agreed by the owner (G-006), and each run reports the change in the unmatched count. Legacy cache rows are re-run through the new matcher during migration; disagreements are reported and removal needs owner approval at G-004.
D-033 [R4] Recently Added semantics: take the 20 most recent matched releases, newest first; unmatched releases are skipped and reported; truncate to at most 100 tracks at whole-album boundaries; zero matched releases aborts without replacing; the snapshot is persisted (encrypted) before the replace and the call order is asserted.
D-034 [R4] Ledger identity and completeness: completion is recorded per (release, target); once read-back has confirmed an item it is never re-added automatically; reconciliation applies only to unknown rows; identity follows provider aliases (Spotify linked_from, YouTube setVideoId); a playlist read is accepted only if complete against the provider total or snapshot; after N consecutive mismatches the target is quarantined and reported instead of re-adding (N unmeasured, A-026). Discogs ingestion deduplicates by instance_id, requires the unique count to equal pagination.items on both the first and last page, re-fetches page 1 at the end and fails closed if it changed, treats an empty non-final page as an error, and parses Retry-After as seconds or HTTP-date within a total-wait budget.
D-035 [R4] State encryption and tokens: a pinned, audited AEAD (cryptography AESGCM) with a fresh random nonce per write, a key-ID header, and rotation by re-encryption; wrong or missing key aborts before any write with no plaintext fallback; a monotonic generation number in the associated data is also published in the public status counter so a rolled-back state is detected up to the last published status (older rollbacks stay undetectable and this limit is accepted); the owner keeps an offline copy of the key; key loss is recovered by treating all ledger rows as unknown and running the G-004 duplicate report; the rotated Spotify refresh token is stored inside the encrypted state and Spotipy uses an in-memory cache handler (no .cache file); the Actions cache and artefact retention are never the source of truth.
D-036 [R4] Test integrity and provider realism: every test file that exists when S-000 completes, not only TEST_PLAN.md, is hashed into FROZEN_MANIFEST.sha256 (the legacy tests/test_sync.py is hashed only after its rewrite) and CI runs sha256sum -c; the executable red tests are written and hashed as the last action of S-000, before any source change; amending a frozen test needs owner approval recorded here; existing tests that contradict D-008 (first-result match) or assert nothing about dry-run side effects are rewritten in S-000; provider tests use recorded, sanitised read-only response fixtures and a fake provider that accepts duplicate items and enforces the 100-item limit; every live run starts with a read-only schema canary that fails closed, YouTube Music is probed with an authenticated call before any write, and typed ProviderError is kept distinct from NoMatch with a breaker on unmatched-rate spikes.
D-037 [R4] Provenance and diagnosis: S-006 first establishes where the legacy cache came from; rows absent from the live Discogs collection are dropped and never written; S-000 records the actual cause of the failed sync runs of 2026-11-07 (candidates: secrets in if, shell interpolation of the YouTube secret) before any rewrite.
D-038 [R4] Gate evidence additions: G-001 states the blast radius of the ytmusicapi credential (a whole Google-account session) and requires a dedicated or Brand account, or removal of YouTube Music; G-003 decides whether the planning-run copies of lessons/, knowledge/ and .checkpoints/ in the product repository are removed; G-005 lists the consequences of each option, including that a private repository loses free Pages (unverified) and the option of a separate private state repository.
D-039 [R4] The local Express routes /api/config, /api/cache/reset and /api/spotify/exchange-token are deleted; if any is kept it binds to 127.0.0.1 only, requires a CSRF token, never accepts credentials in a query string, and its justification passes G-002b.
